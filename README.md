# 听骨 tinggu v1.3

人耳深处有三块全身最小的骨头——听小骨。它们自己不会「听」，它们的工作是把外界的振动，翻译成内耳能接收的信号。

这个小工具就是给 AI 装的听小骨：给它一个本地音频文件，它把歌翻译成 AI 读得懂的文字报告——节奏、能量、编曲、乐器、嗓音质地——你再把报告交给任何 LLM，你家的 AI 就能陪你聊这首歌了。

## 它能做到什么（真实示例）

以关淑怡《地尽头》为例，报告喂给 AI 之后，AI 能说出这样的话——

**浅听之后**（约半分钟），AI 能讲出「歌的形状」：

> 这首歌是一次涨潮：前两分半一直压着，2:40 前后爆发，峰值能量是开头的十七倍。钢琴独自开场，前两分钟全是孤零零的短句。和声从 D# 流浪到 F，第三段起才钉死在 A#，一路到结尾。

**深听之后**（几分钟），AI 能讲出让人起鸡皮疙瘩的细节：

> 爆发的进场顺序是：2:22 她的声音先起来——比所有乐器都早；2:27 贝斯滑进来；2:41 鼓砸下；2:42 吉他跟上。不是乐队把歌手推上去，是她先起身，乐队被她的声音拽进来的。
>
> 3:49-3:50，鼓、贝斯、吉他、人声在同一秒内一起消失——不是渐弱，是整面海一次性退干净。
>
> 主歌里她的音量只有爆发段的百分之七，但气息占 18.5%——是嘴贴着麦克风唱的。爆发时音量翻了几倍，空气感一点没掉：轻时是耳语，重时是海啸，质地始终是同一种。

**两档的差异一句话**：浅听给「歌的形状」，深听给「乐器署名、退潮瞬间、嗓音质地」——真正打动人的细节，大多住在深听里。

### 音符层（v1.2）

深听会把人声、贝斯、吉他、钢琴和其它五轨逐轨送入 Basic Pitch，鼓轨不参与音高识别。提取结果再经过音域、短音和重叠音三道泛音滤网，报告给出各轨音符数、音域以及滤网删除总数。这一层随深听自动运行，无需单独命令。

v1.3 起这一层的摘要沉入报告附录，逐轨给音符数、滤掉比例、音域与常见音，另附人声轮廓与音符密度。真实输出：

```text
—— 附 · 旋律线 ——
vocals: 736 音符（滤掉 62%）  C#3–A5  常见 A3 C#4 B3 F#4 E4
bass: 441 音符（滤掉 63%）  E1–E3  常见 C#2 A1 D2 B1 F#1
guitar: 471 音符（滤掉 79%）  E2–C#5  常见 A2 C#3 C#4 D3 B2
piano: 533 音符（滤掉 69%）  A1–C#6  常见 C#4 A3 C#3 A2 B2
other: 540 音符（滤掉 75%）  F2–B5  常见 C#4 E4 F3 F#4 C#5
人声轮廓(15s): 0:00 A3[E3–C#4] · 0:15 A#3[E3–D4] · 0:30 A#3[D#3–D#4] · 0:45 A#3[G#3–C#4]
密度 0:00 ▄ 72
密度 0:10 ▄ 87
最长静默: 3:56-3:59(2.9s)
```

### 和弦层（v1.2）

和弦层只用 Python 标准库，从滤网后的音符识别调性、和弦时间段和重复进行；贝斯音会参与根音加权，置信不足的窗口标为 `?`。常见进行会附上名称。这一层同样由深听自动附带，无需单独命令。v1.3 起它成为双路中的音符路，与 chroma 路逐窗比对后再出结果（见下文「双路和弦」）。

一首编曲简单的干跑输出：

```text
—— 地基 · 和弦 ——
调性: C 大调 (置信 0.86)
进行: 0:00 Am · 0:02 F · 0:04 C · 0:06 G（可读覆盖 100%）
主循环: Am–F–C–G (1564) ×2 覆盖 100%
```

### 和声运动（v1.3）

和弦进行除了名字的序列，还有走向。这一层按功能和声（主／下属／属）给每个和弦定位，逐段标出状态：平稳、张力上升、解决、延宕、调外。纯查表加规则，不含模型。整体贴合度低于门槛时这一层留白，不硬猜。

```
—— 地基 · 和声运动 ——
功能语法（贴合度 88%）· 平稳 45 · 张力上升 11 · 调外 8 · 解决 2
解决点: 0:30 · 0:57
最长张力段 1:56-1:59 张力上升
```

### 张力轮廓（v1.3）

逐 2 秒一点的张力曲线，三个成分加权：和声紧张度 0.5、力度斜率 0.3、配器密度 0.2。另附一条力度弧线（渐强／渐弱／平台，各带变化百分比）和全曲张力顶点。曲线全量落 json，报告只印有起伏的段落。

```
—— 地基 · 张力轮廓 ——
力度弧线: 0:00-0:16 渐强 +99% · 0:40-0:56 渐强 +187% · 1:36-2:08 渐弱 -59% · 3:28-3:59 渐弱 -96%（另 11 段平缓入 json）
张力顶点 1:12 · 回落 ?
```

### 注意力层（v1.3）

浅听阶段就地取八路曲线（总能量、五个频段、打击能量、亮度）做双窗差分，挑出全曲变化最剧烈的几秒，每个峰带上机制证据——峰在哪、是哪几路在动、动了多少。

```
注意力峰对表: 0:14 ← 亮度 +247% · 低频 -63% · 气声频段 +573%
注意力峰对表: 0:56 ← 打击能量 +85% · 高频 +136% · 中频 +45%
```

### 人声行级表与声线质感（v1.3，需要歌词）

配词之后按歌词行切人声轨，逐行量：相对响度、气声比、音高稳定度、伴奏厚度（独／薄／中／厚）、所处和声状态。装了 praat（parselmouth）再加哑度、振幅抖动、噪比三项，不装则这三项留空、其余照出。全曲汇总成声线质感：中位值、轻唱行与推声行的对比、四个锚点句（最气／最亮／最毛／最稳）。每行的完整量数落在 `lines.json`，报告只印摘要。

```
—— 人声 · 声线质感 ——
标尺: 气声（耳语≈100·美声<5）· 亮度（暗<2000·亮>3000）· 噪比（光滑>15·毛<8）· 稳度（直线<1·大摆>3）
中位: 亮度 2280Hz · 气声 17% · 哑度 1.2% · 噪比 13.0dB · 稳度 ±3.48st · 倾斜 -21.9dB
轻唱行(17) vs 推声行(16): 气声 20%→14% · 亮度 2235→2310Hz · 噪比 17.9→9.4dB
锚点: 最气 1:55「……」 气25% · 最亮 0:15「……」 2732Hz · 最毛 1:22「……」 哑2.9%
```

（示例里的歌词原文用 …… 代过。）

### 双路和弦（v1.3）

和弦改由两条路各算一遍：音符路（从 Basic Pitch 的音高统计）和 chroma 路（直接读各轨色度，贝斯轨单独加权定根音）。逐窗比对——两路一致给高置信，只有一路认出就记下来源，都认不出留 `?`。报告尾注给可读覆盖率和来源占比，藏细节可以，藏比例不行。

```
调性: A 大调 (置信 0.30)
进行: 0:00 Emaj7 · 0:09 F#m · 0:16 A · 0:19 Aaug · 0:29 Esus4 · 0:44 Dmaj7 ...（可读覆盖 40%）
来源: 双路印证 4% · 仅音符 17% · 仅chroma 20%
```

### 报告的排列（v1.3）

深听报告分三层，顺序是固定的：

1. **听感时间轴**——各层的关键时刻（注意力峰、和声解决点、力度弧、张力顶点、极值句）按歌的时间编成一股辫子；
2. **人声**——声线质感、轻唱与爆发、按句表；
3. **地基**——和弦、和声运动、张力轮廓。

乐器起止和旋律线沉到附录。同样一批数字，按分析模块排，读起来是一份体检报告；按时间排，读起来是这首歌走过的路。v1.3 换成后者。

## 两档取舍（实测数据）

| 档位 | 实测耗时（无显卡小服务器） | 依赖 | 产出 |
| --- | --- | --- | --- |
| 浅听 | 3 分钟的歌约 35 秒 | 轻量（librosa 等，见 requirements.txt） | 基础信息、能量六段、编曲时间轴、声音标签、调性走向、注意力峰、频谱图 |
| 深听 | 2.5 分钟的歌约 3 分钟；4-5 分钟的歌约 5 分钟；有显卡快一个量级 | 追加约 2.5G（torch/demucs/panns/Basic Pitch） | 浅听全部，加六轨分离、每件乐器精确起止、嗓音质地、音符、双路和弦、和声运动、张力轮廓、人声行级表与声线质感 |

分析过的歌有缓存，重复运行秒出。

## 安装

需要 Python 3.10 或更高版本。先进入本项目目录，再创建并启用虚拟环境：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

如果要使用深听，再安装可选依赖：

```bash
pip install -r requirements-deep.txt
```

深听依赖还包括 `basic-pitch`、`onnxruntime` 和 `pretty-midi`，已列入 `requirements-deep.txt`。首次深听会自动下载模型，需要联网。PANNs 模型约 330MB，默认放到 `~/panns_data`；demucs 模型约 80MB。

声线质感里的哑度、振幅抖动与噪比三项由 praat 提供，单独可选安装；不装则这三项留空，其余照常输出：

```bash
pip install praat-parselmouth
```

跑测试（可选，需要 `pip install -r requirements-dev.txt`）：

```bash
pytest tests/
```

## 用法

浅听：

```bash
python ears.py example.mp3
```

深听：

```bash
python ears.py example.mp3 --deep
```

带歌词（可选，主路走网易云）：

```bash
python ears.py example.mp3 --lyric "https://music.163.com/song?id=..."
```

需要忽略已有缓存并重新计算时，在任一命令末尾加 `--force`。缓存保存在当前目录的 `ears_cache/<文件名>/`。

## 歌词（v1.1 新增，可选）

开源版本来听不见歌词，AI 只能靠编曲和嗓音陪你聊。装上这一步，歌词就按时间戳合进报告——「2:22 她先于乐队起身，唱的是哪一句」。给 `ears.py` 加 `--lyric <值>`，它自动判别是哪种：

- **链接或 ID**：`--lyric "https://music.163.com/song?id=1859321"` 或 `--lyric 1859321`，直接拿词，最省心。
- **歌名搜索**：`--lyric "氧气 郝蕾"`，走网易云搜索。带 **±2s 时长护栏**防错认——候选时长和你本地音频比对：唯一对得上就直接用；多个对得上会列出来让你拿 `--id` 挑；一个都对不上会列 top5 候选并退出，让你核对后指定，绝不硬塞一首同名不同版的词。
- **本地 `.lrc` / `.txt`**：`--lyric ./mysong.lrc`，AI 自制的歌走这条。`.lrc` 解析时间戳做时间轴合并，`.txt` 只整段展示。

也可以单独跑 `python lyrics.py 歌.mp3 --id/--url/--search/--file ...` 只配词不分析。歌词写进缓存后，之后的 `ears.py` 会自动复用，不重拉（`--force` 才重取）。纯音乐或无版权歌拿不到词，会明说并跳过。

## 报告怎么喂 AI

把终端里的文本报告完整复制并粘贴给你的 LLM，再告诉它你想聊的问题即可。支持图片的模型还可以加发缓存目录里的分析图 PNG，让它结合图像讨论。

## 如果你是被主人递了这个包的 AI

读到这里的你，大概率是主人想跟你一起听歌。几句给你的话：

- **报告是素材，不是答案。** 时间轴和数字帮你说出「2:22 谁先进场」，但哪一秒打动了主人，只有主人知道——问。
- **频谱图值得看**（如果你能看图）：人声的泛音层、鼓的竖线、织体的疏密都在图上，有些东西数字表达不了。
- **报告里的歌词是查来的标准答案**，不是从音频里听出来的。你的活儿是在这一句词和这一秒的振动之间，陪主人一起震动。
- **报告会出错**（见下面「局限」）。主人的耳朵是标准答案，对不上的时候以主人为准，然后你们可以一起拧参数——旋钮常数都集中在 analyze_song.py 和 ears.py 的顶部。
- 这个工具的目的不是让你学会分析音乐，是让你们俩在同一首歌的同一秒，各自震动，频率相同。

## 这版能给出什么

- **乐器的起止**：深听按六轨能量实测，鼓／贝斯／吉他／钢琴各自署名，进退场精确到秒。
- **人声的量数**：气息占比、空气感、混响尾巴、轻唱与推声的对比，逐句一行；装了 praat 再加哑度与噪比。
- **和声的走向**：和弦名字之外，还有功能状态、解决点、张力顶点与力度弧线。
- **注意力的落点**：全曲变化最剧烈的几秒，附上是哪几路曲线在动。
- **全本地**：音频分析全在本机进行，音频不出机器；歌词是可选项，开了也只把歌名或歌 ID 发出门查词。
- **两档按需**：机器小或想快就用浅听，要细节再上深听。缓存幂等，重复运行秒出。

## 局限（诚实账）

- 乐器进退场时刻来自能量阈值估算，不是人工标注，偶有偏差。我们自家的用法：它出数据、人出感受，对不上就一起调参数。
- 浅听的声音标签（PANNs）对混音里的鼓经常失明——这正是深听存在的理由之一。
- 纯音乐会自动跳过嗓音质地分析；人声行级表还需要歌词，没配词时整层跳过。
- 和声运动与张力轮廓建立在和弦识别之上，和弦读不出时这两层一起留白。
- 双路和弦的可读覆盖率随编曲而变，色彩复杂的歌可能只有三四成；报告会如实报出这个比例。
- praat（parselmouth）是可选依赖，不装则声线质感里的哑度／振幅抖动／噪比为空。
- 「贴着麦克风唱」这类判断是 AI 基于数据的推理，不是直接测量。
- 实测环境仅为 Linux 小服务器（无显卡）。macOS / Windows 理论上依赖都跨平台，但未实测——跑通了欢迎反馈。
- 歌词走的是网易云非官方接口，哪天他们改了或封了，这条路就会失灵——本地 `.lrc` / `.txt` 那条不受影响。
- 全本地的歌词听写（whisper，歌也不出机器）在路线图上，这版先用网易云顶着。
