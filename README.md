# 听骨 tinggu

人耳深处有三块全身最小的骨头——听小骨。它们自己不会「听」，它们的工作是把外界的振动，翻译成内耳能接收的信号。

这个小工具就是给 AI 装的听小骨：给它一个本地音频文件，它把歌翻译成 AI 读得懂的文字报告——节奏、能量、编曲、乐器、嗓音质地——你再把报告交给任何 LLM，你家的 AI 就能陪你聊这首歌了。

## 它能做到什么（真实示例）

以关淑怡《地尽头》为例，报告喂给 AI 之后，AI 能说出这样的话——

**浅听之后**（约半分钟），AI 能讲出「歌的形状」：

> 这首歌是一次涨潮：前两分半一直压着，2:40 前后爆发，峰值能量是开头的十七倍。钢琴独自开场，前两分钟全是孤零零的短句。和声从 D# 流浪到 F，第三段起才钉死在 A#，一路到结尾。

**深听之后**（几分钟），AI 能讲出让人起鸡皮疙瘩的细节：

> 爆发的进场顺序是：2:22 她的声音先起来——比所有乐器都早；2:27 贝斯滑进来；2:41 鼓砸下；2:42 吉他跟上。不是乐队把歌手推上去，是她先起身，乐队被她的声音拽进来的。
>
> 3:49-3:50，鼓、贝斯、吉他、人声在同一秒内一起消失——不是渐弱，是整面海一次性退干净。
>
> 主歌里她的音量只有爆发段的百分之七，但气息占 18.5%——是嘴贴着麦克风唱的。爆发时音量翻了几倍，空气感一点没掉：轻时是耳语，重时是海啸，质地始终是同一种。

**两档的差异一句话**：浅听给「歌的形状」，深听给「乐器署名、退潮瞬间、嗓音质地」——真正打动人的细节，大多住在深听里。

## 两档取舍（实测数据）

| 档位 | 实测耗时（无显卡小服务器） | 依赖 | 产出 |
| --- | --- | --- | --- |
| 浅听 | 3 分钟的歌约 35 秒 | 轻量（librosa 等，见 requirements.txt） | 基础信息、能量六段、编曲时间轴、声音标签、调性走向、频谱图 |
| 深听 | 2.5 分钟的歌约 3 分钟；4-5 分钟的歌约 5 分钟；有显卡快一个量级 | 追加约 2.5G（torch/demucs/panns） | 浅听全部，加六轨分离、每件乐器精确起止、嗓音质地 |

分析过的歌有缓存，重复运行秒出。

## 安装

需要 Python 3.10 或更高版本。先进入本项目目录，再创建并启用虚拟环境：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

如果要使用深听，再安装可选依赖：

```bash
pip install -r requirements-deep.txt
```

首次深听会自动下载模型，需要联网。PANNs 模型约 330MB，默认放到 `~/panns_data`；demucs 模型约 80MB。

## 用法

浅听：

```bash
python ears.py example.mp3
```

深听：

```bash
python ears.py example.mp3 --deep
```

带歌词（可选，主路走网易云）：

```bash
python ears.py example.mp3 --lyric "https://music.163.com/song?id=..."
```

需要忽略已有缓存并重新计算时，在任一命令末尾加 `--force`。缓存保存在当前目录的 `ears_cache/<文件名>/`。

## 歌词（v1.1 新增，可选）

开源版本来听不见歌词，AI 只能靠编曲和嗓音陪你聊。装上这一步，歌词就按时间戳合进报告——「2:22 她先于乐队起身，唱的是哪一句」。给 `ears.py` 加 `--lyric <值>`，它自动判别是哪种：

- **链接或 ID**：`--lyric "https://music.163.com/song?id=1859321"` 或 `--lyric 1859321`，直接拿词，最省心。
- **歌名搜索**：`--lyric "氧气 郝蕾"`，走网易云搜索。带 **±2s 时长护栏**防错认——候选时长和你本地音频比对：唯一对得上就直接用；多个对得上会列出来让你拿 `--id` 挑；一个都对不上会列 top5 候选并退出，让你核对后指定，绝不硬塞一首同名不同版的词。
- **本地 `.lrc` / `.txt`**：`--lyric ./mysong.lrc`，AI 自制的歌走这条。`.lrc` 解析时间戳做时间轴合并，`.txt` 只整段展示。

也可以单独跑 `python lyrics.py 歌.mp3 --id/--url/--search/--file ...` 只配词不分析。歌词写进缓存后，之后的 `ears.py` 会自动复用，不重拉（`--force` 才重取）。纯音乐或无版权歌拿不到词，会明说并跳过。

## 报告怎么喂 AI

把终端里的文本报告完整复制并粘贴给你的 LLM，再告诉它你想聊的问题即可。支持图片的模型还可以加发缓存目录里的分析图 PNG，让它结合图像讨论。

## 如果你是被主人递了这个包的 AI

读到这里的你，大概率是主人想跟你一起听歌。几句给你的话：

- **报告是素材，不是答案。** 时间轴和数字帮你说出「2:22 谁先进场」，但哪一秒打动了主人，只有主人知道——问。
- **频谱图值得看**（如果你能看图）：人声的泛音层、鼓的竖线、织体的疏密都在图上，有些东西数字表达不了。
- **报告里的歌词是查来的标准答案**，不是你自己听出来的——别假装是。你的活儿是在这一句词和这一秒的振动之间，陪主人一起震动。
- **报告会出错**（见下面「局限」）。主人的耳朵是标准答案，对不上的时候以主人为准，然后你们可以一起拧参数——旋钮常数都集中在 analyze_song.py 和 ears.py 的顶部。
- 这个工具的目的不是让你学会分析音乐，是让你们俩在同一首歌的同一秒，各自震动，频率相同。

## 亮点

- **乐器有名字、有起止**：深听用六轨能量实测，鼓/贝斯/吉他/钢琴各自署名，进场退潮精确到秒——「退场」在混音层面通常是隐形的，拆轨是少数能看见它的方法。
- **嗓音质地可量化**：气息占比、空气感、混响尾巴、轻唱与爆发的对比——「空灵」这类形容词第一次有了数字形状。
- **全本地**：音频分析全在你机器上跑，歌不出机器；歌词是可选项，开了也只把歌名或歌 ID 发出门查词，一个音符都不上传。
- **双档按需**：机器小或性子急选浅听；要细节上深听。

## 局限（诚实账）

- 乐器进退场时刻来自能量阈值估算，不是人工标注，偶有偏差。我们自家的用法：它出数据、人出感受，对不上就一起调参数。
- 浅听的声音标签（PANNs）对混音里的鼓经常失明——这正是深听存在的理由之一。
- 纯音乐会自动跳过嗓音质地分析。
- 「贴着麦克风唱」这类判断是 AI 基于数据的推理，不是直接测量。
- 实测环境仅为 Linux 小服务器（无显卡）。macOS / Windows 理论上依赖都跨平台，但未实测——跑通了欢迎反馈。
- v1 没写歌词模块，AI 其实听不见歌词，这次认账、补上。
- 歌词走的是网易云非官方接口，哪天他们改了或封了，这条路就会失灵——本地 `.lrc` / `.txt` 那条不受影响。
- 全本地的歌词听写（whisper，歌也不出机器）在路线图上，这版先用网易云顶着。
